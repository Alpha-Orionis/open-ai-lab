# 成长路径与成果标准

以真实交付为依据，阶段可以交叉或跳过。以下为自查与评审标准，不是考试、资格认证或固定学制。

| 阶段 | 学习内容 | 推荐交付 | 可验证标准 |
| --- | --- | --- | --- |
| Level 1 · AI Learning | Python 基础、AI 基本概念、工具使用、Git/GitHub、Markdown | 小示例或文档改进，以及首个 PR | 能解释改动，提供复现步骤，完成一次评审反馈 |
| Level 2 · AI Building | 需求拆解、API、数据处理、测试、评测、团队协作 | 一个可运行的 AI 功能 | 有清晰输入输出、环境说明、验证记录和失败案例 |
| Level 3 · Research Track | 论文阅读、基线复现、实验设计、Benchmark、模型改进 | 实验包与研究报告 | 数据和配置可追溯，有对照实验、误差分析和局限说明 |
| Level 3 · Career Track | 模块设计、工程化、部署、可靠性、产品表达 | 可演示的应用与作品集案例 | 有运行/部署说明、测试或评测、成本与限制说明及个人贡献证据 |

## 建议学习顺序

1. 用简单示例理解输入、模型调用、输出以及结果的不确定性。
2. 掌握分支、提交、PR、Issue 与评审协作。
3. 选定一个应用问题，先做最小可运行版本，再补充测试与评测。
4. 根据兴趣深入科研或工程；允许在同一项目中轮换角色。

## 成果评审

贡献者先在 PR 或项目报告中自查，维护者结合交付内容评审。主要看问题价值、技术理解、验证质量、协作与表达。没有维护者评审支持的任务应先缩小范围或标记暂停，不以活动频率给成员排名。

阶段完成后可将 Issue、PR、演示与实验记录整理成贡献说明；所有能力表述应与本人实际贡献一致。

## 贡献者成长机制

| 步骤 | 贡献者行动 | 同伴或维护者支持 | 保留证据 |
| --- | --- | --- | --- |
| 进入 | 说明兴趣与可投入时间，选择范围合适的任务 | 帮助明确问题、验收和依赖，确认是否有评审支持 | Issue 中的协作约定 |
| 实践 | 尽早提交可检查的 Draft PR 或实验记录 | 通过小范围 Review 提供具体反馈，必要时结对排查 | PR、讨论、配置与中间结果 |
| 交付 | 补齐验证，回应评审，解释自己的改动 | 根据验收标准复核，记录未解决问题 | 合并记录、测试或实验结果、演示 |
| 复盘 | 整理“问题—本人工作—证据—结果与限制” | 对技术理解、协作与表达给出改进建议 | 贡献说明与下一步任务 |
| 承担职责 | 按意愿尝试任务拆分、评审或项目协调 | 提供职责范围和交接支持，按治理规则确认角色 | 角色约定、评审与维护记录 |

不要求达到固定 PR 数量才进入下一阶段；复杂问题分析、负结果、测试、文档与有效 Review 都可成为证据。研究与就业方向允许切换、交叉和轮换角色，同一份成果可以同时展示研究与工程贡献，但需说清本人实际完成的部分。

## 角色与平台成员身份

Learner / Contributor 描述参与方式；Project Lead / Maintainer / Mentor 描述具体职责，均不是按学习时长自动晋升的等级。正式 GitHub 成员身份或仓库权限由维护需要决定，不是参与公开贡献的前提，详见 [治理章程](../GOVERNANCE.md)。

当前已建立 [Infinite-Monkey-Lab 组织](https://github.com/Infinite-Monkey-Lab)，尚无阶段证书机制。贡献者可以使用公开成果建立作品集，不把社区角色或参与记录表述为学历、资格认证或就业保证。
