# 新成员入门

目标：完成一次有实际价值、可验证的开源贡献。

## 准备

- 一个 GitHub 账号与可用的 Git 环境。
- 文档贡献可以直接从 Markdown 和项目说明开始；代码贡献按具体项目配置环境。
- 阅读仓库首页、贡献指南及协作规范，了解目前处于筹备阶段。

## 第一周建议

| 步骤 | 要做的事 | 完成标志 |
| --- | --- | --- |
| 了解 | 阅读成长路径与首个项目提案 | 能说明自己想解决的一个具体问题 |
| 选题 | 找一个入门 Issue，或提出一个有价值的小改进 | Issue 中写明目标、范围与验收方式 |
| 实作 | Fork、创建分支、修改文档或示例 | 改动可独立检查，链接与步骤有效 |
| 交付 | 提交 PR、回应评审 | 提供验证记录，并完成反馈修改 |
| 回顾 | 记录学到的内容与下一步 | 关联 Issue、PR 和成果链接 |

进度按个人情况调整。找不到任务时，可以尝试按新成员视角检查入门流程，记录实际遇到的问题，再提出修正方案。不要为增加提交数量创建没有内容价值的改动。

## 贡献记录建议

在自己的作品集或学习日志记录以下内容，无需向本仓库提交个人信息：

```text
解决的问题：
我的具体贡献：
Issue / PR 链接：
运行、测试或实验结果：
评审中做出的改进：
限制与下一步：
```

如果计划投入一个较大任务，先在 Issue 中确认维护者是否能够提供评审支持。
