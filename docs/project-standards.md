# 项目成果与发布标准

本标准用于判断一个项目是否可以从提案进入开发、展示或持续维护。它不代表本仓库已经具备应用代码、测试、Demo 或研究结果。

## 开始开发前

- 有具体用户与问题、最小范围、输入输出，以及暂不包含的内容。
- 有愿意承担职责的项目负责人、维护者和评审支持。
- 数据、模型、外部代码的来源与许可可追溯，使用方式与授权范围一致。
- 计算资源、API 费用上限与承担方明确，不默认要求学生付费。
- 任务拆为小工作包，每项有依赖、交付物和可操作的验收方式。

## 正式应用的最小成果包

| 方面 | 交付与检查方式 |
| --- | --- |
| 项目说明 | 中英文简介、用户场景、当前状态和已知限制，区分计划与已实现功能 |
| 可运行性 | 依赖版本、配置占位示例、启动说明与合法可用的示例数据；新环境能按步骤运行 |
| 基本测试 | 核心路径、异常和关键边界的测试或可重复检查，记录运行环境与结果 |
| 质量评测 | 明确数据集、指标、基线、评价方法与失败案例，不用演示效果替代系统评测 |
| 公开成果 | 可复现的本地演示、演示截图/视频或实验结果；云端公开服务不是硬性条件 |
| 协作证据 | Issue、PR、Review、分工和个人贡献说明，保留原始作者 |
| 发布说明 | 明确版本、对应 commit、验证人、复现结果、费用边界和未解决问题 |
| 许可与数据 | 独立仓库有自己的 LICENSE；分别标注第三方代码、数据、模型及内容许可 |

校园知识助手还需覆盖引用溯源、资料不足时拒答、错误处理与可回答/不可回答用例，具体阈值在实现前共同确认。

## 科研成果的额外交付

- 研究问题、可检验假设、相关工作与贡献边界。
- 数据集版本、来源、许可、切分方式与泄漏检查。
- 环境、模型版本、硬件、随机种子、参数和运行命令。
- 固定基线与评价协议、对照和适用时的消融实验。
- 原始记录、重复实验差异、成本、负结果及误差分析。
- 使用 [实验记录模板](../templates/experiment-report.md) 写明结果、局限和分工。

没有运行的实验标为计划或估算，近似复现说明差异。署名依据实际贡献与投稿规则讨论，不以组织职位或提交数量换取。

## 代码、内容和资源许可

当前仓库原创内容继续遵循已有 MIT 许可，不在此次更新中追溯更换。未来独立代码仓库可评估 MIT 或 Apache-2.0；独立教程内容是否采用内容许可，由权利人确认后清楚标注适用范围。

公开可见不等于可复制或再分发。外部资料、模型权重和数据集分别核对许可，授权不明确时使用自写示例或不纳入交付。只在配置示例中填写占位值；真实密钥与私有资料不进入公开贡献。

## 评审与发布流程

贡献者按标准自查 → 维护者检查 Issue/PR → 由另一位协作者尽可能在新环境复现 → 记录通过与未通过项 → 决定发布、缩小范围或延后。暂时没有复核者时明确标记“尚未独立复核”，不写成已验证结果。

新增应用时安排与实际风险相匹配的 Actions 检查。项目长期缺少维护人力时标记维护状态、整理接续说明，必要时暂停或归档。
