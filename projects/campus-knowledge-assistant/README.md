# Campus Knowledge Assistant · 校园知识助手

**状态：项目提案，尚无可运行代码。**

## 要解决的问题

公开校园指南、办事说明和课程资料通常分散在不同文档中。我们希望提供一个面向小规模、合法可用资料的问答原型，回答时标注可核对的来源；找不到依据时明确说明。

## 最小版本范围

- 使用人工整理的一组公开、允许使用的资料，或社区自行撰写的示例资料。
- 支持文本或 Markdown 资料的离线导入与检索。
- 提供问答入口，展示回答、原文片段、来源标题与位置或链接。
- 资料不足时能够拒答；用例覆盖有答案、无答案、冲突和过期资料。
- 先支持本地运行，模型与检索方案在技术提案中讨论。

暂不处理学生个人数据、账号登录、校内私有系统或自动执行校园事务。公共可访问不等于可再分发，资料进入仓库前需核对使用许可；授权不明时使用自写示例。

## 建议评测方案

先整理至少 30 条人工检查的问题，区分可回答和不可回答问题。将开发样例与最终评测集分开；固定数据版本与参数，避免用测试集调参。具体指标与验收阈值在实现前通过 Issue 确认。

- 检索：在有答案的问题上记录 Recall@k，并说明相关文档如何标注。
- 回答：人工核对事实是否得到资料支持，以及引用是否指向支持该结论的片段。
- 拒答：统计不可回答问题上的正确拒答，以及可回答问题上的误拒答。
- 工程：记录测试环境、响应时间和调用成本；区分测量值与估算值。

## 启动门槛与完成标准

开始编码前，先明确维护者、数据许可、模型方案、费用上限和技术分工。最小版本完成时应有：

- [ ] 合法可用且可追溯的示例数据。
- [ ] 全新环境可按 README 启动的应用。
- [ ] 有来源引用、拒答与异常处理的端到端流程。
- [ ] 基线与评测报告，包含失败案例与局限。
- [ ] 测试步骤、演示以及关联的 Issue / PR。
